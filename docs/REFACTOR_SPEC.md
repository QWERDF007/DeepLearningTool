# 架构收敛实施规格

## Problem Statement（问题）

用户在同一个桌面项目中导入数据、编辑标注、训练模型、评估预测及运行高级功能。这些操作跨越 GUI、后台线程、外部进程、数据库与文件系统；当前实现仍存在提交和取消结果不一致、关闭入口时序不完整、操作中断恢复缺口、界面同步重工作和状态投影分叉。结果可能是数据已修改却提示失败、进程未正常结束却显示成功、打开评估或标注时界面卡顿，以及重开项目后目录与记录不一致。

已有项目聚合、数据工作流、模型生命周期、任务身份、几何工具、评估缓存和分层测试应继续复用。问题在于这些实现之间的契约尚未全部闭合，不以重新命名或增加模块数量作为解决方案。

## Solution（解决方案）

按阶段 0—9 补齐现有公开用例的输入、提交、取消、恢复及结果发布契约。用户能够安全停止和关闭项目，准确获得数据和模型操作结果，复用预测完成正确评估，并在参数配置、高级功能和安装环境中获得一致行为。

此规格规定目标和验收，不记录完成进度。架构理由与静态源码证据集中在最终方案；每项静态发现必须由实施阶段补行为验证。已有实现只需补缺和验证，不要求重新实现。

## User Stories（用户故事）

1. 作为项目用户，我希望关闭项目后不再接受新任务或写入，以便安全切换到另一个项目。
2. 作为项目用户，我希望关闭等待期间仍能获知任务状态，以便判断不可中断计算是否仍在结束。
3. 作为项目用户，我希望重复停止只产生一次终态，以便任务状态和提示始终一致。
4. 作为项目用户，我希望旧运行的进度和结果不会覆盖新运行，以便重试任务不受迟到事件影响。
5. 作为项目用户，我希望停止、失败或完成后恢复编辑，以便继续配置下一次运行。
6. 作为项目用户，我希望重开项目后仍能看到准确耗时和终态，以便追溯运行结果。
7. 作为数据用户，我希望导入失败或取消时恢复原有数据和类别属性，以便失败操作不改变项目。
8. 作为数据用户，我希望复制、移动和划分原子更新相关记录，以便图片、标签与标注不脱节。
9. 作为数据用户，我希望提交后发生取消仍报告真实已提交结果，以便界面与数据库一致。
10. 作为数据用户，我希望导出到源文件所在位置时不会删除源文件，以便保留原始数据。
11. 作为数据用户，我希望失败的覆盖导出保留原目标，以便已有成果不被半成品替换。
12. 作为数据用户，我希望 UNC 和本地路径正确解析，以便产物写入我指定的位置。
13. 作为数据用户，我希望导出结果按本次实际产物验证，以便旧文件不能掩盖遗漏或取消。
14. 作为数据用户，我希望取消批量导出后不再启动下一数据集，以便停止整批工作。
15. 作为数据用户，我希望批次进度和最终耗时真实显示，以便判断工作是否推进。
16. 作为标注用户，我希望不同格式复用几何规则，以便导入导出后区域位置一致。
17. 作为标注用户，我希望小区域保留到展示过滤阶段，以便不丢失有效异常轮廓。
18. 作为模型用户，我希望创建和复制中断后能够恢复一致模型，以便重开时不出现孤立记录。
19. 作为模型用户，我希望重命名和删除同时处理目录与索引，以便名称与实际文件一致。
20. 作为模型用户，我希望恢复清理失败仍保留恢复依据，以便下一次可以继续处理。
21. 作为测试任务用户，我希望任务改名或删除中断后可恢复，以便预测和任务索引不失联。
22. 作为模型用户，我希望新预测失败时部分产物不被当作完整预测，以便评估可信。
23. 作为训练用户，我希望成功等待进程正常退出并校验产物，以便完成消息不掩盖后续崩溃。
24. 作为模型用户，我希望当前运行的非法协议明确失败，以便不会静默留下错误进度。
25. 作为模型用户，我希望训练和推理参数按实际框架含义解释，以便理解参数效果。
26. 作为模型用户，我希望修改推理参数仅保存值，以便自行决定何时重新推理。
27. 作为评估用户，我希望评估参数提交实际变化后复用已有预测，以便避免重复推理。
28. 作为评估用户，我希望无预测或值未变化时不启动评估，以便避免无效计算。
29. 作为评估用户，我希望热力图阈值只重建必要视觉结果，以便保留已有数值和区域。
30. 作为评估用户，我希望从全部真实分数切分点求最佳 micro-F1，以便最优阈值不受图表采样影响。
31. 作为评估用户，我希望相同最佳 F1 选择最高阈值，以便最佳值确定且可复现。
32. 作为评估用户，我希望每个测试任务仅首次自动应用最佳阈值，以便后续保留我的选择。
33. 作为评估用户，我希望原图与热力图上的区域坐标一致，以便正确理解异常位置。
34. 作为评估用户，我希望修改当前训练配置不改变旧预测的几何解释，以便历史结果保持一致。
35. 作为评估用户，我希望可见缩略图按需加载，以便打开大量图片时仍能操作界面。
36. 作为评估用户，我希望多任务缓存总量可控，以便长时间切换任务不会持续占用内存。
37. 作为评估用户，我希望生成失败退出 Busy 并保留评估数值，以便仍可查看已有成果。
38. 作为评估用户，我希望正常和异常保持两组分布且提示清晰，以便解释当前阈值与最佳阈值。
39. 作为高级功能用户，我希望智能标注推理不阻塞界面，以便推理期间仍能查看状态和停止。
40. 作为聚类用户，我希望写回使用启动时的输入并准确报告部分失败，以便数据集变化不造成隐式写错。
41. 作为设置用户，我希望保存失败保留未保存状态并给出错误，以便不会误以为设置已生效落盘。
42. 作为参数用户，我希望控件创建和选项刷新不自动改值，以便浏览页面不触发业务操作。
43. 作为数据用户，我希望批量刷新保留选择且不反复重建整棵树，以便筛选与浏览稳定。
44. 作为开发者，我希望单层测试缺少前置产物时直接失败，以便检查每层真实责任。
45. 作为开发者，我希望 full 模式能从空项目完成真实流程，以便验证模块组合和最终产物。
46. 作为部署者，我希望测试和运行包不依赖开发机固定路径或旧 DLL，以便在新环境复现。
47. 作为维护者，我希望每个阶段有失败测试、Release 构建和 CTest 证据，以便区分实现存在与验收完成。

## Implementation Decisions（实施决策）

### 共同契约

1. **所有权**：项目拥有项目数据库、任务、可变缓存和展示投影。应用级共享对象不保存当前项目的可变业务事实。
2. **线程**：worker 接收冻结的值、路径、取消令牌和必要 Adapter；连接在使用线程创建并释放。GUI 对象只在所属线程访问，业务 worker 不回读 Qt Model 或 manager 的当前值。
3. **终态**：完成、失败、停止均为终态，重复停止可安全调用；终态持久化和通知只发生一次。任务完成后恢复编辑，迟到事件不能恢复运行或覆盖结果。
4. **关闭**：先关闭新任务及用户写入入口，再对全部执行者发出取消，等待实际工作和必要完成处理，最后释放资源。关闭期间允许清理、回滚和终态持久化，不允许新业务写入。
5. **事实源**：数据库定义归 schema，参数元数据归 YAML，原始预测归任务产物，任务状态归唯一状态写入口；展示与缓存只作可重建投影。
6. **结果**：成功必须与数据库和真实文件一致。失败、取消、部分完成与待恢复必须能区分，错误包含对象、阶段和资源上下文。
7. **结构**：只按职责、所有权、变化轴和可测试 seam 拆分。不得按 2000 行或其他行数强制拆分，不新增无行为的转发层。

### 行为口径

- 非 `evaluation` 参数修改仅保存值，不自动启动推理或评估。用户显式推理时使用新值；推理成功后自动评估。
- `evaluation` 参数编辑提交且值实际变化时，仅在已有预测上评估；无预测或值未变化不触发。当前模型忙时禁用编辑，其他模型不被无关锁定。
- 热力图阈值属于视觉派生：遵守评估忙状态和串行生命周期，复用已完成数值及 polygon，仅更新必要热力图。
- 停止是终态，不提供暂停；“禁止终态写入”指拒绝迟到业务事件，不禁止终态本身落库，也不禁止终态后用户编辑下一次任务配置。
- 进程可以超时 terminate/kill；不安全强杀进程内线程。第三方计算无取消能力时等待其返回，期间拒绝新工作并显示关闭中，不能假报停止或提前释放依赖。
- 失败、取消不能用 100% 伪装成功；成功完成才报告完整进度。
- 仅为实际支持的 schema 版本提供显式迁移，不为废弃任务、参数分组或旧协议增加兼容逻辑。

### 分阶段实施步骤

#### 阶段 0：建立可复现基线

**解决什么**：区分已有实现、实际缺陷和规划目标，避免用历史文档或测试数量判断完成。

**步骤**：

1. 核对工作区、相关 WORKLOG 与目标模块源码，保留无关改动；记录本阶段要验证的用户行为。
2. 从 CMake target、DDL、任务协议、参数 YAML 和测试注册定位唯一入口，标出实际依赖与生命周期拥有者。
3. 配置测试并通过 CTest 列出目标；对即将修改的行为运行相关测试，保留失败原因和最小复现。
4. 性能问题固定真实输入、冷/热缓存条件和测量方法，再采集基线。

**完成条件**：每个待改问题均有代码入口、行为验收和可执行验证路径；没有把未运行的历史测试描述为本轮通过。开发初期不运行全量测试。

#### 阶段 1：冻结后台输入，统一结果发布

**解决什么**：后台操作读取不断变化的页面状态，或回调直接写入已经切换的项目。

**步骤**：

1. 沿 DataOperationWorkflow、模型任务准备、评估及 Feature 调用链检查跨线程捕获，先补“提交后修改选择/参数”的隔离测试。
2. 在拥有当前状态的线程一次构造请求，明确数据选择、参数、绝对路径和执行身份；复用现有请求类型。
3. worker 使用自身连接及文件资源，返回领域结果；GUI 接收时校验归属及运行身份后应用投影。
4. 移除回读 manager、并行可写快照及失效的旧发布路径。
5. 统一 DataIO 与 Workflow 的取消/结果来源；并行执行先等待全部 worker 退出再读取异常，不能因异常检查早于 join 而吞掉失败。
6. 取消由实际提交者裁决：提交前取消回滚，提交后必须发布真实结果；禁止工作流仅根据收到取消请求就把已提交成功改成失败。

**完成条件**：提交后的选择变化不影响正在运行的请求；项目切换或同任务重新运行后，旧回调不改变新结果；取消与销毁测试无跨线程对象访问。控制最后一个 worker 抛出异常仍报告失败；在提交完成和回调应用之间取消，数据库与展示必须一致。

#### 阶段 2：收敛 Schema 和持久化入口

**解决什么**：表结构、表类型、运行时 SQL 和业务状态分别演化，批量写入出现半成功。

**步骤**：

1. 复用 DatabaseSchema 与 DDL，补空库、结构错误、未知版本、事务失败测试。
2. 确定 SQL 正本及 sqlpp11 类型的生成或一致性校验入口；删除重复建表语句。
3. 对实际 schema 变更增加显式版本迁移，在一个事务内完成并更新版本；失败保留原库结构和数据。
4. 将受改动用例的连接、批量事务及错误封装在 database；领域结果采用已有强类型 Record/Result，动态类型仅留在协议和 QML 边缘。
5. 按任务数据的拥有者收敛状态、参数和选择的持久化，删除不可重建的平行写入。
6. 将现有手写结构检查与正本自动比对，覆盖外键、唯一约束和必要索引；复制/划分等单库操作采用一个领域事务，不能用忽略错误的补偿删除替代。
7. 明确普通测试、训练及内部子任务的持久化归属；复用现有任务存储入口，记录数值耗时、运行身份和首评应用事实。内部子任务不被强加普通测试评估 schema。

**完成条件**：支持版本可初始化/升级，未知版本明确失败；注入中途失败后无部分记录；表类型与正本有自动校验；业务流程不拼 SQL、不传递跨线程连接。字段与表的完整定义只留在 DDL。

#### 阶段 3：收敛项目关闭、停止和迟到回调

**解决什么**：关闭等待期间仍可写入，顺序等待导致其他任务尚未收到取消，Busy 结束与执行者结束混淆。

**步骤**：

1. 通过 ProjectManager 的公开关闭流程，测试等待期间 queued 回调尝试创建数据集或启动任务；同时覆盖重复停止、Pending 子任务和项目切换。
2. 将“拒绝新工作并请求取消”与“等待清理完成”分开表达；所有入口先进入关闭状态，清理可重复调用但不能提前返回遗漏等待。
3. 先向全部数据、Feature、模型、评估/聚合及外部进程发出取消，再等待；共享线程池不能逐个取消一个拥有者后等待整个池。
4. 等待以实际执行句柄和完成处理为准，包含 DataIO、后续批次及必要回滚；不使用可能被关闭回调跳过更新的 UI 标志替代。
5. 拒绝失效身份的进度和结果；必要终态落库后释放数据库及投影。
6. 将应用页脚进度改为任务进度的只读聚合，启动、更新和完成均匹配运行身份。
7. 区分协议完成上报和最终成功：实际执行者退出且必要产物校验后才发布成功；停止也等待实际执行者收敛。

**完成条件**：关闭后重开数据库，关闭期间尝试的新数据不存在；工作与完成回调均收敛后才释放对象；同名重启、重复停止、关闭中失败不会重复通知或污染新项目。两个任务交错结束不会关闭对方进度；先上报 finished 再异常退出不能显示成功。不可中断的底层计算按行为口径处理并有验证记录。

#### 阶段 4：统一数据操作、路径与几何

**解决什么**：格式 Adapter 各自处理公共规则，路径错误仍报成功，尺寸/裁剪/padding 换算不一致。

**步骤**：

1. 复用 DataIO 格式工厂与 DataOperationWorkflow，将公共批次、取消、进度、结果校验集中到实际拥有者。
2. 统一路径解析：无歧义的绝对路径或明确根目录下的相对路径；UNC 保留网络语义，错误地址不能相对应用目录落盘。
3. 导入先校验再事务写入；导出创建/校验目标，按批次报告进度，结束核对真实文件与必要内容；明确失败、取消的残留处理。
4. 复用 GeometryKernel，统一 rectangle/Mask/polygon 及 resize、中心裁剪、padding 的变换上下文；删除页面或格式内重复换算。
5. 为移动、复制、删除、划分检验同样的快照、取消和数据库投影规则。
6. 导出拒绝源/目标同一文件及别名；覆盖使用暂存后发布，失败不得先删除原目标。校验依据是本次实际完成的文件清单，旧目录文件不能计入成功。
7. 整批导出共享取消身份，取消后不再启动下一数据集。导入改由 worker 事务写入，失败同时恢复已有类别属性等修改，不只删除新增记录。
8. 区分存储几何与视口交互变换；Mask 带孔、退化轮廓及栅格取整按格式实际表达能力验证，不承诺所有格式无损往返，也不擅自增加新的区域表示。

**完成条件**：Folder、Mask、LabelMe、COCO 往返测试校验固定夹具的准确数量、类别、尺寸及区域；损坏输入和路径失败不能成功结束；中途取消不留虚假完整数据。几何测试用固定坐标验证正反映射、裁剪边缘及非方形图片，不能仅截图目测。

#### 阶段 5：模型目录与数据库一致恢复

**解决什么**：模型创建、复制、重命名、删除跨数据库和文件系统，进程中断造成两边事实不同。

**步骤**：

1. 以 ModelLifecycle 和 ModelStorageService 为入口，通过公开行为测试固定复制范围、名称冲突及内部引用要求。
2. 审查已有操作日志、staging/quarantine 和发布顺序，补齐每个实际中断窗口；同卷原子重命名不能假定跨卷也成立。
3. 在文件发布和数据库提交前后注入失败，验证即时回滚或明确待恢复。
4. 通过关闭/重开项目触发已有恢复入口，验证重复恢复安全，并清理完成操作的临时产物。
5. 将稳定 UUID 在首次副作用前写入恢复凭证；数据库插入后、日志 ID 更新前中断，恢复必须能按 UUID 找回记录。清理失败保留恢复凭证，不标记恢复完成。
6. 同一一致性契约覆盖测试任务创建/重命名/删除及索引更新；耗时模型复制、恢复扫描不得在 GUI 执行，仍复用已有生命周期接口。

**完成条件**：四类模型操作及测试任务目录操作的成功、权限/占用失败、数据库失败及中断恢复均有证据；逐个覆盖数据库提交前后、日志更新前后和清理失败；重开后模型列表、身份、目录、参数和任务引用一致。已有用户目录不得作为失败测试的破坏目标。

#### 阶段 6：任务协议、参数与持久化

**解决什么**：双端事件与任务状态不一致，参数显示/存储/执行含义漂移，运行时间依赖 Python 上报。

**步骤**：

1. 沿 TaskManager、ExternalModelTaskRunner 和 EasyTrain task 协议定义单一消息契约，补字段、身份、状态顺序、异常退出和停止测试。
2. 在协议入口严格解码；合法但已失效的运行消息丢弃，当前运行的非法协议明确报错，不误伤其他任务。
3. 收敛状态写入口，C++ 生命周期计算运行时间并沿持久化链路保存；重开项目恢复终态和耗时。
4. 逐项对照仓库内实际框架代码审查参数名称、说明、默认值、范围、步长及传参位置；保留明确产品选择：batch 默认 8，数据加载进程默认 2、上限 128，不新增 auto。
5. 按行为口径验证 inference/evaluation 的提交触发及运行中编辑锁；推理完成自动评估使用同一份预测。
6. 预测替换先在本轮工作区生成并验证，提交完整身份及索引后才成为可评估输入；失败/取消的部分预测不得混入已发布结果，不能仅以目录存在作为完成依据。
7. 为同一协议提供双端合法/非法样例；未知状态、错误字段类型、进度越界在修改状态前拒绝。未绑定身份的错误只拒绝连接/消息，不失败任意任务。

**完成条件**：双端协议用同一组有效/非法样例验证；缺失身份、错误类型和错误状态有明确结果；零退出码缺产物不能成功；Python 不再上报时 UI 计时仍推进，停止后重开耗时一致；参数从 YAML 到界面、数据库和框架调用的键和值有行为验证。产品指定默认值与框架默认值明确区分，FS-SAM2 只验证内部任务契约。

#### 阶段 7：评估正确性与按需可视化

**解决什么**：重复读取和计算拖慢评估，阈值搜索与展示混淆，热力图和多边形位置/生命周期不一致。

**步骤**：

1. 复用 IEvaluationEngine、EvaluationResult 和缓存，明确预测读取、数值计算、实例索引及视觉派生的内部职责。
2. 用小规模可穷举样例验证全部有限去重分数切分点上的全局 micro-F1；相同最优 F1 选择最高阈值。图表约 100 点采样不能影响最优解。
3. 每个测试任务仅首次评估自动应用最优阈值，在同一次评估内刷新结果；后续只展示最佳值，保留用户配置。覆盖重开任务、重评估和重新推理。
4. 图像级统计复用预测摘要；完整分数图只在必要读取中物化，原图尺寸和缩略图按需获取；移除全像素文本哈希与无筛选重复聚合。
5. 原始 TIFF 只读；分类阈值用于原始像素分割。连通区域提取仅可丢弃不足 3 个轮廓点的结果，面积过滤交给展示代理。
6. 热力图采用统一分数尺度，模型坐标系下与 polygon 共用预处理；关热力图时将 polygon 反映射到原图。复用检查页红色 polygon 组件。
7. 可视化在后台按需生成，合并重复请求、限制缓存字节数；切换筛选和控件缩放不无故重算，重新推理使旧派生失效。
8. 验证首次打开、多次切换、切换混淆矩阵、失败、取消和关闭；生成结束必须退出 Busy，失败保留评估数值并回退原图及已有 polygon。
9. 快照身份获取避免 GUI 全表读取、逐项序列化和目录扫描；无关模型修改不使当前预测失效。完整输入读取放入后台稳定快照流程。
10. 跨任务缓存共享项目总预算，并限制排队请求；聚合任务可取消，不能只用计数器丢弃输出而保留所有后台计算。
11. 几何解释使用生成预测时的预处理快照，不能以当前训练参数解释旧预测；仅热力图阈值变化复用数值及 polygon，按评估生命周期刷新视觉。

**完成条件**：穷举对照得到相同最优阈值及指标；首评自动应用不产生第二次评估；原始 TIFF 字节不变；非方形、crop、padding 夹具中的热力图/多边形坐标一致；原图与热力图切换均稳定显示区域。异常分布保持正常绿色、异常红色，两组分布及只读阈值线不新增额外图例。

**性能验收**：同机同输入分别记录冷启动、重复打开、仅改评估参数、筛选与重新推理后的耗时、内存峰值、实际读取/生成次数和 UI 事件响应。重复打开命中可复用结果；视觉生成量受请求实例约束；缓存达到上限后稳定回收；关闭取消不遗留队列。必须给出前后数据，不能凭异步线程或新增缓存宣称优化完成，也不预设未经测量的统一秒数。

#### 阶段 8：Feature 用例与 QML 单一投影

**解决什么**：聚类等流程依赖完整 manager，数据集已创建但流程报失败，页面 Busy 和编辑状态各自维护。

**步骤**：

1. 复用各 Feature 控制器，明确输入、执行与写回接口；worker 不访问完整项目对象。
2. 将聚类目标数据集创建和结果写回纳入同一用例结果，覆盖创建失败、写回失败、取消、重复请求及旧回调。
3. 智能标注模型替换及小样本子任务继续沿现有运行身份和终态规则收敛。
4. QML 只绑定权威状态和结果；复用现有 Header、QuiComboBox、QuiToggleSwitch、弹窗及 polygon 组件，移除平行业务状态。
5. 智能标注从同步 infer 改为执行者拥有 predictor 的异步请求；取消、模型替换及项目关闭统一收敛，不能仅因模型加载异步就视为推理不阻塞。
6. 聚类冻结来源/目标定义，写回前检查冲突；单库写入事务完成，跨文件失败明确部分完成与恢复结果。
7. 设置保存返回明确结果，失败保留 dirty 状态；缓存失效监听权威字段变更。参数联动合法性归 C++，控件刷新不自动 commit。
8. 树模型名称/颜色局部通知，结构变化按批次合并，用稳定 ID 保留选择；核心类型名称与支持列表由单一元数据集合派生。

**完成条件**：Feature 通过真实下一层依赖及必要 Adapter 独立测试；目标数据集与报错语义一致；组合任务全部收敛后才通知终态；真实 UI 验证运行中锁定、停止、失败恢复、滚动及控件布局。设置写入失败不显示已保存；打开/刷新参数控件不改值；单项名称修改不全树 reset，批量结构变化保留合法选择；智能标注计算期间 GUI 事件仍可响应。

#### 阶段 9：构建、发布和完整验收

**解决什么**：仅在开发机或旧 DLL 环境下运行，安装依赖与测试依赖缺失，子层 fixture 静默补齐前置条件。

**步骤**：

1. 审查真实 target DAG、公开头和安装导出，缺失 imported target 在配置时明确失败，不伪造空目标。
2. 复用 AddTest.cmake 的源码发现和测试环境注入，验证新增测试可被脚本正确选择。
3. 从独立安装目录运行消费方探针与桌面烟测，验证 DLL、QML、模型配置及可配置依赖，不依赖开发机偶然 PATH。
4. 先完成相关层级验证，再运行 ordinary、Model/QML、项目级独立负向用例及 full；命令来源见测试指南与脚本 `--help`。
5. 删除已替代的旧写入口、协议、状态投影和临时高频日志；修正本次涉及的文档索引和失效链接。
6. 修正公开头安装布局及构建绝对路径泄漏，完善应用安装入口；现有运行包和 CMake 安装分别验证。发布包布局检查不替代真实启动。
7. 统一 sanitizer 选项，按编译器配置 flags；最低 CMake 版本覆盖实际使用能力。普通测试临时目录尊重环境并可使用系统临时目录。
8. 删除确认无调用的空迁移入口和纯别名；实际 target DAG 通过消费方配置/链接验证，不只匹配源文件顺序。

**完成条件**：Release 构建、安装消费、桌面烟测和规定 CTest 均通过；单层缺少项目/数据集/模型/权重/预测时失败且不创建前置产物；full 在明确的测试根目录完成真实 PatchCore 流程，产物可由软件打开查看。Python 和第三方路径可覆盖。


## Testing Decisions（测试决策）

### 测试 seam 与既有测试基础

优先从用户实际经过的最高公开入口测试；一条用例只有一个最终结果断言来源。全链路通过项目入口组合验证，算法规则通过现有评估/几何接口验证，不强迫所有测试启动完整应用。真实下一层依赖保留，仅在外部计算、进程或文件失败等需要稳定注入的地方使用已有 Adapter。

| 入口 | 验证内容 | 既有基础 |
| --- | --- | --- |
| ProjectManager | 关闭、切换、重开与写入隔离 | 项目关闭集成测试 |
| DataManager / DataIO | 数据事务、格式产物、批量取消与进度 | 导入、导出、Workflow、分层项目测试 |
| ModelManager / ModelLifecycle | 目录和记录一致性、中断恢复 | 模型生命周期及故障存储 Adapter 测试 |
| ModelTaskController / TaskManager | 实际进程终态、身份、协议和耗时恢复 | 模型任务、Pending 停止、Python 协议测试 |
| IEvaluationEngine / GeometryKernel | 阈值、指标、坐标及预测复用 | 阈值搜索、几何、评估缓存测试 |
| Feature 控制器 | 智能标注、聚类写回与组合任务关闭 | Feature 生命周期测试 |
| 参数/设置公开模型与 QML 控件 | 无副作用刷新、保存失败、忙状态、选择 | 参数行为、树模型角色、评估 QML 测试 |
| CMake 消费方与工具入口 | 真实依赖、安装及测试选择 | 依赖探针、Model 测试选择、打包校验测试 |

不以私有字段、类名、文件数量、源码正则匹配替代行为断言；已有 CMake 文本顺序测试仅作结构提示，实际依赖需配置和链接验证。并发测试通过可控执行者和屏障构造顺序，不依赖固定 sleep 碰运气。

### 阶段交付门槛

1. 缺陷先有失败行为测试，新需求先有可执行预期；测试穿过公开接口及真实下一层依赖。
2. 改动后相关 Release target 构建成功，测试统一经 CTest 执行；不直接启动测试 EXE。
3. 按改动风险验证失败、取消、重复调用、关闭、迟到结果或中断恢复，不机械给纯布局改动附加无关测试。
4. 对需要真实资源的阶段运行真实资源验证，纯单元测试不能替代训练、共享路径或桌面交互证据。
5. 审查职责、依赖方向及 SSOT，旧路径已删除，调用方无需了解新增内部复杂度。
6. 代码阶段按 WORKLOG 规则记录命令、结果及未验证项；缺少环境的检查明确未完成。spec 不记录阶段完成勾选，不形成第二份账本。


### 真实资源与性能验收

普通测试使用内存或临时资源；项目级使用固定图片/Mask、真实项目和可注入 Python 环境。单层默认复用且禁止 fixture 补齐前置；full 在明确指定的测试目录重建全链路。重建清理不能作用于用户项目或不明确的根目录。

性能验收比较相同机器、相同输入的冷/热缓存场景，覆盖单任务和多任务切换，记录端到端延迟、GUI 事件响应、读取/生成次数、排队工作、内存峰值和取消收敛时间。无相关输入变化不应重新扫描/生成；总缓存达到预算后回收稳定。仅声明“已移到后台”不能通过验收。

## Out of Scope（非目标）

- 不更换技术栈，不拆成网络服务，不添加通用消息总线、插件框架或全仓统一大重写。
- 不为符合角色名称而新增 Context/Workspace/Runtime 类，不按文件行数、测试数量或类数量验收。
- 不兼容废弃参数组、旧任务协议或旧评估 revision；不顺带删除用户历史任务。
- 不修改 Anomalib 内部算法，不为展示重复推理，不修改原始 TIFF，不新增评估/热力图/多边形持久化格式。模型操作恢复日志不属于视觉结果格式。
- 不自动启动参数修改后的推理，不增加暂停，不锁定无关模型，不新增面积过滤规则。
- 不使用无界缓存、全像素浮点转文本、高频日志或不安全线程终止掩盖结构问题。
- 不把所有数据库表包装成公开 Repository，不把领域协议、事务与业务流程搬入 common 或 QML。
- 不把本规格交付视为代码实施完成；本次文档工作不包含源码修改、构建或测试执行。
