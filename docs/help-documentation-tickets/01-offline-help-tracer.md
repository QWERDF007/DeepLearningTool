# 01: 最小离线帮助闭环

**What to build:** 用户在未打开项目的桌面应用中，通过“帮助 → 文档”打开随程序发布的最小中文手册；断网阅读两篇相互可导航的有效页面、查看本地图片并搜索中文内容。开发、安装和发布使用同一行为，失败能够给出明确反馈。

**Blocked by:** None (can start immediately).

**Status:** completed

**Spec:** [实施决策](../HELP_DOCUMENTATION_SPEC.md#implementation-decisions) D1—D11；[测试决策](../HELP_DOCUMENTATION_SPEC.md#testing-decisions) T1—T7；用户故事 1—9、22—30。先完成代表性离线验收，再接入菜单和发布，全部属于本票据的同一完整链路。

- [x] 两篇页面说明本项目真实的帮助使用或概念，包含中文正文、交叉导航和至少一张有效本地图片，不使用空页面或未实现功能占位。
- [x] 在 Edge 与 Chrome 的无预热缓存会话中断网打开产物，验证本地导航、中文搜索、结果跳转、主题及支持的高亮，记录锁定版本组合的真实结果。
- [x] 先编写帮助公开入口、菜单和发布失败路径的定向行为测试，再实现；遵守 T1 的依赖边界，不新增面向 QML 的路径解析接口。
- [x] 帮助菜单只有文档项，无项目时可用；右上角边界、鼠标、键盘、Esc 和焦点恢复均验证通过，一次选择只触发一次打开请求。
- [x] 从公开帮助入口打开真实文件，正确处理中文、空格和 URL 特殊字符；改变工作目录不改变定位结果。
- [x] 缺失文件、目录误用、不可读文件和系统拒绝请求遵守 D10，各自通过真实环境或确定性边界测试；一次失败只有一条通知。
- [x] 关闭文档构建时普通应用构建不要求文档 Python 依赖；开启时按 D7、D9 得到实际可打开的产物。
- [x] 同一文档目标进入 CMake 安装和现有发布链路；发布包不依赖源码、参考工程、训练 Python 环境或服务器。
- [x] 内容和图片修改可以重建；删除页面后干净发布中无旧页面残留，必要资源及链接检查通过。
- [x] 强制文档生成失败或移除必要资源时，发布明确失败，不沿用旧产物、不宣告发布完成。
- [x] 移动实际发布包到含中文和空格的目录，改变工作目录，断网从程序菜单打开并完成阅读与搜索，遵守 T6。
- [x] 检查发布资源无远程加载依赖，源码副本及开发文档未进入用户站点；不是只检查首页存在。
- [x] 定向测试与真实浏览器验证证据记录到唯一任务账本，源码和索引保持单一事实源，应用仍可编译运行。
